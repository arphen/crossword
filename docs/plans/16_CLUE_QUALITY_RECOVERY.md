# Clue quality recovery: the defects, and the slices that fix them

Execution plan, 1 October 2026. Written against the implementation at `codex/finished-crossword` (`8322933`), which is the parent of this branch, and against the host this plan is partly to be executed on: Apple M3, 8 cores, 16 GB unified memory. [The active specification](06_PERSONAL_EPISTEME.md) keeps ownership of the backlog; the slices below are proposed as rows `Q01`–`Q08` and as amendments to `E05`, `E06`, `E10` and `E18`. The conceptual companion is [the self-critique](15_THE_SELF_CRITIQUE_OF_THE_CONCEPT.md) §4–§7; this document is where that critique becomes a queue. It inherits the completion rule of the active specification: *a task is complete when its acceptance artifact exists, not when an API stub or a model prompt exists.*

## 0. The short version

The complaint is accurate, and it is not one bug. Four of the five defects below are in the host, not in the model, and none of them is improved by a larger model. Each is stated with the code that produces it.

1. **"Pun" is a punctuation count.** `_clue_family_observation` assigns the family `pun` to any clue that ends in a question mark (`private_puzzle_generation.py:648`–`656`), and the prompt contract in the same file tells the model that a pun must "end with ? and use a concise alternate-reading question" (`:96`). The scorer counts the surface the generation contract asks for. The code is honest about this — every observation carries `confidence: "surface-signal-only"` and `uncertainty: ["semantic-family-unverified"]` (`:666`–`668`) — but the Tuesday recipe then computes `minimumNonDefinitionFamilies: 5`, `minimumNonDefinitionCount: 40` and `targetNonDefinitionRate: 0.72` from those labels. A pun that is only a question mark is not a pun, and no existing check has ever asked whether it is.
2. **A clue may contain the answer's own stem.** `_answer_lexical_forms` (`:2822`–`2861`) generates plurals, tenses and `-S/-ES/-ED/-ING` variants; it has no degree or derivation rule, so `SHADY` is not a form of `SHADIER`. "more shady" therefore returns no overlap from `_clue_answer_overlap` (`:2864`–`2882`), matches none of the six generic-template regexes (`:184`–`242`), and trips no morphology rule because `_COMPARATIVE_MARKER_RE` (`:438`–`440`) matches only the literal convention marker `comparative` or `(comp.)`, never the word *more*. The clue is admitted whole. It is worth naming what it actually is: the comparative of *shady* **is** *shadier*, so the surface is not a leak that happens to be near the answer — it is the answer's own definition with the answer's own morphology folded into it. `Q01` fixes exactly this and nothing else.
3. **Genre is not modelled.** The guards are six anchored `fullmatch` regexes over closed vocabularies, so `Famous singer's name` is rejected while any other name-shaped clue is admitted — `Name of the singer in a 1980s British band` passes every rule in the file. The family fallback is `definition` (`:662`), which absorbs every boring clue without naming its kind. Nothing counts name-shaped clues, so nothing caps them, and a name-shaped answer with no source-backed sense has no better clue available to it.
4. **The model is asked for one clue per entry and takes the offer.** `_MODEL_GENERATION_POLICIES` (`:892`–`952`) contains timeouts and token budgets and no sampling parameter whatsoever: no temperature, no top-k, no seed. One request writes the whole board at 48 tokens per entry (`:918`). There is no candidate set, no comparison, no rejection followed by resampling. The one component that asked the model to judge its own output, `_challenge_private_clues`, is disabled unless an operator sets the environment variable (`:4906`ff). "It just returns the first thing it thinks of" is not an opinion about the model; it is a description of this architecture.
5. **The host can currently only subtract.** Of 165 commits since 20 September, 69 touch this one file and 84 of the 166 subject lines concern clues, guards, repairs or templates — and every one is a filter, a floor, or a retry bound. Filters limit what a generator may emit; they do not produce goodness, and a filter set grows monotonically until it explains nothing. That is why nineteen study artifacts and a 0.944 non-definition rate have not changed what the solve feels like.

## 1. What this machine can and cannot run

The blocker is not the machine. It is that the registry only admits 26–31 B models, and `_installed_model` raises `Install Gemma 4 26B or Qwen 3.8 27B in Ollama to make a local puzzle` when none is present (`:1020`–`1029`); `_EXPLICIT_MODEL_TAGS` (`:878`–`883`) and `runtime_readiness._DEFAULT_MODEL_TAGS` (`runtime_readiness.py:38`–`43`) repeat the same four tags. Verified on this host: Ollama is not installed at all (no binary, no `~/.ollama`, nothing listening on `127.0.0.1:11434`), Homebrew 7.0.7 offers `ollama 0.34.4`, 24 GiB is free on `/`, and `sysctl iogpu.wired_limit_mb` returns `0`, i.e. the driver default of about two-thirds of 16 GB ≈ 10.2 GiB for Metal.

Two consequences, both uncomfortable and both load-bearing. A small model writes worse *first drafts* than the Gemma 26 B on the other machine; `Q07` exists to test the claim that k drafts plus host-side admission beats one draft from a bigger model, against that machine's frozen outputs. And the machine constraint is a gift: at 30–45 tok/s a candidate-set loop finishes in the time the 26 B spends on a single draft, so the architecture `Q07` wants is the only one this host can run at all. Smaller is not the compromise. It is the forcing function.
## 2. Why 165 commits did not change the experience

The loop has been: see a bad clue, add an anchored regex, re-run the study, record a better family rate, see a new bad clue. Every step is locally reasonable and the set of steps goes nowhere, because the quantity that improves is produced by the same surface features the prompt instructs the model to write. The receipts show the mechanism exactly. Study v1 (`seed 20470389`, 78 entries) recorded `definition: 58`, `fill-blank: 14`, `pun: 2`. Study v5 (`seed 20470406`, 74 entries) reached a `nonDefinitionRate` of 0.892 by recording `definition: 8`, `pun: 9` — and `fill-blank: 57`, three quarters of the board written as `___` blanks. It still reported `floorMet: False`, because the floor required five families and only three were present. Study v14 (`seed 20470420`, 72 entries) reached 0.944 with `pun: 19`, `fill-blank: 21`, `nonverbal-expression: 10`, `metalinguistic: 9`, `spoken-equivalent: 9`, `definition: 4`, and passed.

Read those three rows as the player does and the complaint stops being subjective. Between v1 and v5 the objective was satisfied almost entirely by the cheapest contract available: put a blank in the clue and the boring clue counts as a non-definition family. Between v5 and v14 it was satisfied by spreading punctuation across the board. At no point did any receipt contain a quantity that could fall while the puzzle got better, or rise while it got worse. A metric that the generation contract can satisfy is not a measure of the phenomenon, and a floor expressed in *distinct families present* invites a board where every family is present once and nothing is good. Any plan that raises a floor without changing what is counted will reproduce this result, faster.

The second reason is thinner. The nineteen study artifacts total twenty-four boards, all on one model tag, and the one instrument built to compare models — `scripts/model-evaluation-report.py` over the paired holdout — reports `winnerClaim: "none"` and `decisionStatus: "undecided"`, because nobody has ever recorded which of two clues is better. There is no corpus of preference anywhere in either repository. Until there is one, "better" can only ever mean "not the last bad thing I saw", which is the exact shape of the last 165 commits. [Note 15](15_THE_SELF_CRITIQUE_OF_THE_CONCEPT.md) §7 called this the missing catalogue; here it is a missing file.

**And nothing was ever kept.** Every field in a study artifact is a counter — `familyCounts`, `signalCounts`, `issueCounts`, `nonDefinitionRate`, `floorMet`, `timingsSeconds` — and not one of the nineteen contains a single clue surface. The answer-free rule that makes the evidence honest also makes it amnesiac: the exact clues that motivated each regex were discarded at the moment they were measured, so no fix in the last 165 commits can be re-examined against the case that produced it, and no two clues can be placed side by side to see which is better. This is why §2 of this document can quote family counts and cannot quote a clue.

## 3. The inversion the slices implement

Three changes of state, each independently testable, each of which moves authority from the model's first token to something the host can check.

1. **Witness before label.** A clue does not have a family; it has a witness. A pun needs a pivot present in the surface with two distinct senses. A hidden word needs the source span. A fill-blank needs the marked blank. A spoken equivalent needs the quoted utterance and its label. Where no witness exists the clue is `definition` and says so. Receipts then report verified and unverified counts side by side, and the gap is reported rather than closed by assumption. This answers the pun complaint properly: the complaint was never that puns are rare, it is that the count of puns was never a count of puns.
2. **Candidate set before first draft.** k drafts per entry, sampled with real temperature and per-candidate seeds; deterministic admission first (leak gate, witness check, template distance, crossing support); then one comparison call over the surviving three at most, which must name the difference, with the rejected draft retained in the receipt. Budget at k=4, 48 tokens per draft, 40 surfaces, 35 tok/s: roughly 180 s of drafting plus 40 s of comparison — the same wall clock the 26 B spends on its single draft. The saved latency is spent on search, not on parameter count.
3. **Specimen before floor.** A frozen set of clue/answer pairs carrying verdicts — `leak`, `tautology`, `name-slot`, `pseudo-pun`, `acceptable`, `better-of-pair` — becomes the object every scorer is scored against, and the paired holdout finally gets the judgment data it has been waiting for. It is the only artifact that can state a rate of boring, and `more shady` is its first entry.

These are ordered deliberately. Nothing that generates is worth changing until something can tell a good clue from a bad one without a human in the loop for every case, and nothing can be counted honestly until the label it counts is a witness rather than a character.

## 5. Sequencing

Two independent tracks, and they should run in parallel because one of them needs the other machine and neither blocks the other.

Track A is offline and finishes on this host with no model at all: **Q01 → Q03 → Q04 → Q05**. Q01 is half a day, is the only slice that fixes a bug you have already named, and cannot regress anything else. Q03 is what gives every subsequent claim a denominator. Track B makes this machine able to run the pipeline: **Q06**, which is a registry change plus a `brew install ollama` and a 2 GB pull, and then **Q07**, which needs both tracks. **Q02** runs alongside everything, because it is the one artifact no code can produce. The rule between them: no prompt or generation change lands before Q03 has re-scored the corpus against it, because that rule is the only thing the last 165 commits failed to have.

**Stop doing, stated plainly.** Do not raise another family floor; the floors are satisfied and the clues are still bad. Do not add another anchored generic-template regex; Q08 removes the six that exist. Do not attempt a 26 B model on this host. Do not tune the prompt by hand against an anecdote — with Q02 in place there is no excuse for that particular form of guessing, and without it there is no way to know whether a prompt change helped. Do not fine-tune anything: there is no preference corpus, and Q02 is what would make a future fine-tune meaningful rather than expensive.

## 6. What this plan does not know

Four things are assumed and could be wrong, and each has a slice that would show it. The witness requirement may be too strict for `fill-blank` and `spoken-equivalent`, whose witnesses are nearly the surface itself — and `fill-blank` is precisely the family the corpus already abused to satisfy the floor, so Q04 should expect its counts to fall and should be read as a correction rather than a regression. The curated homograph ledger may be too small for pun admission to fire often enough to matter, in which case the honest move is to admit the OEWN pack under `E04` rather than to pretend the ledger is a sense inventory. A 3 B model may fail the JSON schema often enough that per-entry candidate generation costs more in re-drafts than it earns in selection; Q06's receipt measures schema failure per tag before Q07 is scheduled, and `gemma3:4b` exists as the alternative if `llama3.2:3b` is too weak at structure. And twenty-four boards is a thin base for a rate of anything — enough to reproduce a complaint, not enough to settle a claim — which is why Q03 reports counts rather than percentages where the denominator is small, and why Q07 must generate its own comparison boards rather than reusing the corpus. There is also a live question the plan cannot answer locally: whether quality on the 26 B is worth the round trip to the other machine at all. That question is Q07's, and the plan is written so that either answer is an artifact rather than a rework.

## 7. Evidence and registration rules the slices must respect

Artifacts follow the existing pattern `private-<study>-v<N>[.<qualifier>].<model|scope>[-<YYYYMMDD>].json` and are filed by the operator under `docs/evidence/`; the `Q0x` names above already conform, and `offline` and `synthetic` mark the runs that used no model. Each receipt carries a top-level `version`, a `scope`, an `interpretation` line stating that it is a surface-and-mechanical observation, `uncertainty` labels, and a `studyDigest` computed as `sha256` over the canonical sorted-key JSON, per `clue_quality_evaluation.py:22,39`–`42,347`. Anything answer-bearing — which includes the Q02 specimen ledger and the review bundles — stays outside the evidence tree and commits only its counts and digest. Docs link the file *and* its digest. New files require `make map-update` before the branch can pass, since `REPO_MAP.md` is regenerated by the `pre-push` hook from the filesystem.

Two local commands are enough for most of Track A: `uv run --no-sync python -m pytest tests/ -m "not live_provider"` (the `make test` target) and `npm --workspace @crossword/domain run test` for the grammar lane. `make test-live` and `scripts/private-clue-study.py` require a running Ollama and are Track B.

**Q01, today.** It is half a day, it is offline, it is the bug in front of you — a clue that contains the answer's own stem and a definition that is the answer's own comparative — and it produces the first artifact the rest of the plan can be measured against. Then Q03, so that from the next board onward there is text to score, and the last sixteen weeks stop being an argument from memory.
